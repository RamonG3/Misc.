# RuneScape TCG: notes for Claude Code

Ramon is designing a RuneScape-themed 1v1 trading card game. This folder holds two things:

1. **The balance simulator (Python, repo root).** `cards.py`, `engine.py`, `bot.py`, `planner.py` and the round scripts. `README.md` records every balance round; `HANDOFF.md` covers the current state and what's next.
2. **The Arena (`web/`).** A browser game in the style of MTG Arena, played against a bot on PC, on a Pixel 7 Pro phone (landscape), or with an Xbox controller. It is the main thing being built now.

Read `HANDOFF.md` before starting. If the job is AI opponents, also read `BOTS_BRIEF.md`. If it is online play, accounts or the cloud save, also read `ONLINE_BRIEF.md`. If it is Story Mode, read `STORY_BRIEF.md` and `STORY_CH1_SCRIPT.md` (Project docs) and `STORY_OPPONENTS.md`.

## Ground rules

- **Never change the rules in only one place.** `web/engine.js` is a line-for-line port of `engine.py`.
  - A rules change goes into both, then into `cards.py` → `python export_cards.py` → `web/cards.json`.
  - Check it with the parity tests in `web/test/`.
  - Never hand-edit `web/cards.json`.
  - Rules changes are Ramon's call; don't make one unasked.
- **Edit `web/arena.src.html`, never `web/dist/arena.html`.** `python web/build_arena.py` inlines into one self-contained file:
  - fonts, card data and art (`arena_assets.js`, which is generated by `arena_assets.py` from `art/img`);
  - the recorded spell sounds (`arena_sounds.js`, generated by `arena_sounds.py` from `art/sounds`);
  - `engine.js`, `bot.js`, `arena_audio.js`, `deckwiz.js`, `deckrules.js`, `referee.js` (for its time limits only), `online.js`, `cloudsave.js`, `packs.js` and `story.js`, plus the rules' version stamp (`window.RSTCG_VERSION`).
  - The art and the sounds live on Ramon's PC (`art/`), never in this public repo, and neither do the two generated files. `python web/recover_generated.py <built page>` gets the generated files back out of a built page.
  - Each has a `/*__NAME__*/` placeholder in a `<script>` tag. A new module needs a placeholder plus a line in `build_arena.py`.
- **The built file must stay self-contained.** No network at runtime and no CDN libraries, because it is published as a claude.ai artifact and will be hosted on Netlify.
  - Inlined code can't contain `</script` or `</style` (the build asserts this).
- **Duels must stay deterministic.** A saved duel resumes by replaying only the human's decisions.
  - Anything that affects the game must use the engine's seeded `RNG`.
  - Never use `Math.random()` or `Date.now()` in game logic. UI-only randomness, like pack sparkle or idle-menu art, is fine.
- **Once a device has been online, the server is the bank** (`ONLINE_BRIEF.md`, phase 3b): `profile.gp`, `.coll` and `.packs` are its copy. Change them through the bank (`bankClaim`, `bankPack`, the `reset` request), never by hand, or the next `bankApply()` undoes it. Pack odds and the starting collection live in `web/packs.js` only (the page and the server both use it).
- **A new migration goes live before the push that needs it.** The Action deploys the `duel` function but never touches the database; apply migrations through the Supabase connector (`apply_migration`), then `get_advisors`.
- **Online, the server referees.** `web/referee.js` runs the duel on Supabase (the `duel` Edge Function, `server/`), rebuilding it from the seed and the move list on every request, and sends each player only what they may see. See `ONLINE_BRIEF.md`.
  - A new field on the engine's `Player` or `Game` must be sorted into public or hidden in `referee.js` (`referee_test.js` fails until it is).
  - Anything that changes `engine.js` or `cards.json` changes the version stamp, so the function must be deployed again (the GitHub Action does it on push; the repo has the token).
  - Online duels on the page never run the engine: see "Online duels" below.
- **Save keys are versioned.** Players' saves live in `localStorage`:
  - `rstcg-profile-v1`: GP, collection, decks, tutorial state, `story` (Story Mode: `main`, `replay`, `roads`, `claimed`); and `cloud`, the account this progress was last saved to (its id, the revision, and the save both sides agreed on). `progressNow()` is the profile without it;
  - `rstcg-arena-duel-v1`: the duel in progress;
  - `rstcg-settings`, `rstcg-arena-setup`, `rstcg-speed`;
  - `rstcg-online-v1`: the sign-in (a guest's or an account's), your online name, the online duel you're in (its log and last picture), and a trip to Google under way (`flow`);
  - `rstcg-backup-v1`: the progress that "which progress do you keep?" last replaced;
  - `rstcg-bank-v1`: the bank as this device last heard it (`{ uid, bank, claims, packRef, replace, story }`): the bot duels not yet reported, a pack being bought, a replace not yet sent, Story Mode rewards not yet sent.
  - Don't break their shape. If you must change it, migrate the old data, because Ramon has real progress saved.
- **UI text is plain English.** Short sentences, RuneScape flavour, no jargon.

## How the Arena is put together (`web/arena.src.html`, about 6,000 lines)

**One stage, sized to the screen, scaled to fit.** `stageFor(key)` sets the stage's size for a screen and `fit()` scales it to the window.
- Menus: 760 / 900 / 1080 tall by the window's height (phones, laptops, monitors), and as wide as the window's shape (1200–2560). A 1920×1080 window gets exactly 1920×1080.
- The duel: 1920 wide, `clamp(1920*H/W, 864, 1200)` tall.
- Always use `SW()` and `SH()`, never 1920 or 1080, for anything placed against the right or bottom. `#stage.short` / `#stage.phone` and `html.touch` let CSS adapt. `HANDOFF.md` describes how each screen adapts.

**Rendering is string templates.** `render()` rebuilds `#board` from `ui` state.
- Menus are swapped in with `innerHTML`. A duel that is already showing is redrawn **in place** by `morphInto()`: kept elements get only their differences, matched by `id`, `data-at`, `data-bh` or `data-zoom` (then by position). Rebuilding the tilted table from scratch made phones blink. `window.__arena.morphCheck()` compares the result with a board drawn from scratch; `arena_play.js` and `touch.js` call it.
- So an element a duel animation holds on to can survive the next render. That is fine as long as WAAPI animations on board elements don't use `fill: 'forwards'`.
- Each screen is a function in the `SCREENS` map: `menuHTML`, `pickHTML`, `decksHTML`, `editorHTML`, `wizHTML`, `packsHTML`, `duelHTML`, and so on.
- `SWEEP` sets how menu screens slide between each other. Story Mode's screens (`STORY_FADE`, and its duels) dip through black instead (`runFade`), and a scene's change of place crossfades its backdrop (`BG_FADE`).

**Input goes through attributes, never per-element listeners.**
- Clicks: `data-do="action"` plus `data-v="value"` → `act(what, v)`, one big `switch`.
- Text: `data-input="key"` → one input handler near the editor's `edq`.
- Long-press/hover zoom: `data-zoom="Card Name"`.
- Controller: the gamepad code walks everything with `data-do`. `padDefault()` picks where its focus ring starts.

**The duel.**
- `newConfig()` → `buildGame(config)` → `runDuel(config, decisions)`.
- The human's choices come in through a promise-based agent.
- The bot is `botAgent(LV.makeBot(level, seed))`, which adds the "thinking" pause and the move reveal. The level is in the config, so a resumed duel keeps it.
- `saveGame()` stores `{config, decisions}` after every human decision.

**Animations replay the difference.**
- `snap(g)` takes a picture of the state; `settle(g)` and `playChanges()` compare the last picture with the new one.
- Cards fly, damage mills, and capes tick (`capeTick`). The board itself is always drawn from the real state.

**The tilted table.**
- `TABLE = {w:1920, h:780, tilt:30, pers:1500}`, rendered as `.scene` (perspective) > `.plane` (`rotateX`).
- `proj(x,y)` / `projRect` mirror the CSS 3D maths, for placing flat things over tilted ones.
- The HUD stays flat on top: your hand, the actions grid, the turn panel, End turn, the log tab and the bot's hand of card backs.
- Nameplates (`nameplate()`) show the same hooded stranger for both seats (`playerIcon()`, trim in the seat's colour) and the other side's name (`oppName()`), never the deck's style or name: a deck should give itself away in play, not before (Ramon, 2026-11-15; it matters online).
- Rows: `ROW = {bot:8, you:522, h:250}`.

**Online duels** (`ONLINE_BRIEF.md`; the Online section of `arena.src.html`, after `saveGame`).
- `runOnlineDuel(match)` sits beside `runDuel`. The page keeps a `Game` it never plays (`odGame`), sets it to each picture the server sends (`odPut`), and plays each move with what followed it through the bot duel's animations (`odStep`: `showMove`, `liftYourCard`, `settle`). The other player's hand and deck are `'?'` cards; `odReveal` names the card a move takes out of their hand in the last snapshot, so the animation can follow it.
- `ui.od` holds the online duel: the server's move count (`seq`), the decision pending, its deadline, the clock offset, and `chain`, the one queue every request and picture goes through (`odJob`). `odSync()` asks for anything new; Realtime pings (`ON.watch`) and a 250 ms ticker (`odTick`: the clock, deadlines, polling) call it.
- Your choices still go through `ui.pending` (so every prompt, drag and click works unchanged); online, its `resolve` sends the move (`odMove`).
- Words for the other side come from `them()`: the bot's ("Bot", "BOT'S TURN") or the player's ("Ann", "THEIR TURN"). Use it for any new text about the other side.
- `ui.on` holds the Play Online hub (`onlineHTML`: connecting, name, code, waiting room); the deck picker has an online mode (`ui.pickMode`); `ui.result.online` holds a rematch in progress.

**Other systems.**
- **Tutorial:** a scripted first duel (`TUT_*`, `tutChoose`, `coachHTML`, `tutHighlight`) with stacked decks and a scripted bot. Then one-time tips in real duels (`TIPS`). Finishing gives a free pack.
- **Collection and economy:** you start with the three starter decks' cards, and basic materials are unlimited.
  - GP: 100 per win, 50 per loss. A 6-card pack (3 Common / 2 Uncommon / 1 Rare, sometimes Legendary) costs 200 GP.
  - Deck rules: exactly 60 cards, ≤4 copies, ≤1 Legendary, and only cards you own. `deckRules()` checks them, through `deckrules.js`, which the online server uses too.
- **Bots:** `bot_levels.js` (`window.RSTCGLevels`) has the three levels: `makeBot(level, seed)` for `easy`, `normal` and `hard`. `bot.js` stays as it is, and is the normal level. `HANDOFF.md` has the numbers.
  - A bot never reads the other player's hand or the order of either deck. The hard bot's copies of the game (`cloneGame`) deal those out again.
  - The hard bot keeps nothing between decisions, and bounds its search by simulated turns, never by the clock. Its dice for a decision come from the seed and the position.
  - Its playouts run on `engine.js` with the `async`/`await` words stripped (`unwait`). Node makes that copy at load and the build makes one for the page. Never keep a second engine by hand.
- **Deck Wizard:** `deckwiz.js` (`window.RSTCGWiz`) builds a deck around up to 2 focus cards from what you own. It adapts the Starter/Tournament lists, then tests candidates with greedy-vs-greedy games and keeps the best. The UI is `wizHTML` / `wizBuild`.
- **Accounts and the cloud save** (`ONLINE_BRIEF.md`, phase 3; the "Accounts and the cloud save" section of `arena.src.html`).
  - `web/online.js` signs players in (Supabase Auth, no library): `google`, `landing`/`land`, `emailCode`/`emailVerify`, `signOut`, `ways`, and `progress.load`/`save`.
  - `web/cloudsave.js` (`RSTCGCloud`) is the sync and the three-way merge, and knows nothing about the page. `cloudSync()` in the Arena is the only caller; it runs one sync at a time, saves a moment after `saveProfile()`, and backs off quietly when offline.
  - `saveProfile()` is the one way to write the profile: it stores it and schedules the save. Don't call `store.set(PROFILE, …)` directly.
  - A new field in the profile needs a rule in `merge()` (the default is "this device's if it changed it, else the account's"; counters must be added to `NUMBERS`), and `cloud_test.js` should learn it.
  - Signing in only works on a real web address: a page opened from a file or inside the artifact is a `PREVIEW` and says so.
- **The bank** (`ONLINE_BRIEF.md`, phase 3b; the "bank" part of the accounts section of `arena.src.html`). `banked()`: this device has been online as the player now signed in. `bankSync()` opens the bank the first time (with `bankSnapshot()`), sends the queued bot duels (`earn`) and brings back the numbers; `bankApply()` puts them on the profile (the bank's GP plus the duels it hasn't heard of yet). `bankPack(free)` buys a pack at the server. A banked device's cloud save leaves out `BANK_OWNS` (`progressNow()`; `progressAll()` keeps them). Test hooks: `__arena.bank` (`kept`, `sync`, `banked`, `earn`); the stand-in server's `POST /__test/bank` puts GP or cards in a bank.
- **Story Mode** (`HANDOFF.md` "Story Mode"; `web/story.js` and the Story section of `arena.src.html`).
  - The chapters are data in `story.js` with a pure runner node can test; the page only shows steps (`storyPump`) and handles `st*` actions (`storyAct`). A run in the profile points into the script by node id and index: renaming or reordering a node breaks saves, so add steps rather than reshuffling a released chapter.
  - A story duel is a bot duel with `config.story`. Words about the other side come from `them()`, which names the story opponent; never write "Bot" in duel text.
  - Cards with `story: 'boss'` are refused in players' decks (`deckrules.js`); `story: 'reward'` cards are never in packs (`packs.js` `STORY_REWARDS`, `plausible()`), and are given through the bank like everything else.
  - The rules flag `locked_location` (both engines) is only ever set by a story boss fight.
- **The menu's tour:** `TOUR`, `tourStep()`. It changes the menu in place and never calls `render()`.
- **Audio:** `arena_audio.js`. Everything is synthesised except the casting sound of each spell that has a recording and the runecrafting sound of the seven basic runes when played (`RSAudio.clip(name)`, from `window.ARENA_SOUNDS`). It has music layers, an "intense" layer that latches on once either deck is ≤10, and sfx by name: `sfx('tick')` etc.
  - Notes are scheduled 1 s ahead (`LOOKAHEAD`) so a busy page can't make the music drop notes, and touch screens ask for a bigger output buffer. `RSAudio.health()` (Settings → Sound check) reports glitches, dropped notes and the buffer. The busiest battle song costs about half a desktop core to synthesize, so keep new instruments cheap.
  - Two reverbs, one behind each bus, so an echo follows its own volume (one shared reverb into the master once kept the music's echo playing with the music off). Music turned off plays nothing at all (`apply()`).
  - Story Mode has its own tracks: `story` (Tales of Gielinor), `storydark` (Shadows over Draynor: the manor, the stone circle, night) and `boss` (The Ancient Dark, a combat song with an intense layer). `musicFor(key)` in the page picks the `AU.want` for each screen.
  - Recorded clips: `CLIP_GAIN` 2.6 plus a 5 dB low shelf (`CLIP_BODY`), since 2026-11-18; runes play at `RUNE_V` 0.45 so they stay where they were.
  - **A silent layer costs as much as a loud one.** Web Audio synthesizes a note at 1/10,000 volume exactly as hard as at full. The intense layer's notes are only played while it is on or fading out (`intenseUntil`, `catchUp`); do the same for any new layer that waits in silence.

## Gotchas already paid for

- **`zoom` on an absolutely positioned element also scales its `left`/`top`.** Wrap it in an abs-positioned div and zoom the inner element. This is how the discard pile vanished once.
- **Animations in `render()` replay on every render**, because everything is rebuilt. Only animate on a new state, via a class like `.fresh`, or they flicker and look washed out.
- **Card names contain spaces and apostrophes** (`Iban's Staff`, `Green D'hide Body`). Use `esc()` in templates, and never `split(' ')` legal actions.
- **"Elemental Rune" in a card's `req` is not a card.** It means any of Air/Water/Earth/Fire.
- **Hover zoom is mouse-only** (`mouseover`); fingers hold a card instead (`bigZoom`). Taps also send mouse events, so the hover code ignores them for a moment after a touch (`recentTouch()`).
- **Chrome drops a tap that comes within about half a second of a finger drag** in the DevTools-driven tests. `touch.js` waits after a drag. Not seen on a real phone yet; watch for it.
- **Class names are global.** The dragged card's `.ghost` rules once styled `.mchip.ghost` (the dashed "+2 any element" chip from Staff of Light) as a 190×266 card outline. Those rules now live under `#drag .ghost`; scope new generic class names the same way.
- **The database (jsonb) reorders object keys,** and the engine builds a deck in its list's order before shuffling. The referee sorts deck lists by name first; keep anything else that feeds the engine order-independent too.
- **Claude's container and desktop shell can't reach `*.supabase.co`** (the network allowlist refuses it). Use the Supabase connector: `execute_sql` with `pg_net` for live HTTP tests (`server/smoke.sql`), `deploy_edge_function` to deploy, `get_advisors` after schema changes. The desktop app's browser pane can reach it: open the live site there and paste `online.js` into the page to try the real server from a browser (as on 2026-11-16), then delete the test players.
- **Check a layout at several window shapes,** not just 1920×1080: `node web/test/ui/layouts.js` (7 shapes) and look at its shots.
- **Don't centre a menu-screen element with `transform`.** Screens slide in by animating their children's `transform`, which overrides it until the slide ends, so the element jumps. Use `left: 0; right: 0; margin: 0 auto` (as `.onl` does).
- **Test pages that reload need http, not file://.** Playwright's browsers sometimes lose a `file://` page's saved data on reload; `web/test/ui/online.js` serves the page from a little server of its own.
- **Online names are 3 to 12 characters** (the database's rule), so a test player can't be called "Bo".
- **A menu-screen element that is scaled with `transform` jumps the same way** as one centred with it. Put the transform on an inner element (as the crest does), and give the outer one the scaled size, or it will sit on top of its neighbours.
- **Never judge a picture by its size on disk.** Image files copied to Ramon's PC through Claude gain a provenance tag of about 6 KB (MP3 files too; `.ogg` and text don't). Go by pixels (`is_pixel_icon` in `print/build_pnp.py`), and make MP3s on the PC (`arena_sounds.py`) instead of copying them there.
- **After regenerating `arena_assets.js`, compare it with the one before, entry by entry.** The PC's print script and the shipped art have drifted apart before.
- **The page asks the server which ways to sign in are on at most once a minute** (`ON.ways()`), so a test that switches them needs a fresh page.
- **Copy a file to the PC only after the command that writes it has finished.** Sent in the same step, the copy can win the race and deliver the old file.
- **Resuming a bot duel replays your choices silently, then the board catches up with one burst** of the usual animations and effects. That is how it has always been; don't mistake it for moves being played again.
