# RuneScape TCG: notes for Claude Code

Ramon is designing a RuneScape-themed 1v1 trading card game. This folder holds two things:

1. **The balance simulator (Python, repo root).** `cards.py`, `engine.py`, `bot.py`, `planner.py` and the round scripts. `README.md` records every balance round; `HANDOFF.md` covers the current state and what's next.
2. **The Arena (`web/`).** A browser game in the style of MTG Arena, played against a bot on PC, on a Pixel 7 Pro phone (landscape), or with an Xbox controller. It is the main thing being built now.

Read `HANDOFF.md` before starting. If the job is AI opponents, also read `BOTS_BRIEF.md`.

## Ground rules

- **Never change the rules in only one place.** `web/engine.js` is a line-for-line port of `engine.py`.
  - A rules change goes into both, then into `cards.py` → `python export_cards.py` → `web/cards.json`.
  - Check it with the parity tests in `web/test/`.
  - Never hand-edit `web/cards.json`.
  - Rules changes are Ramon's call; don't make one unasked.
- **Edit `web/arena.src.html`, never `web/dist/arena.html`.** `python web/build_arena.py` inlines into one self-contained file:
  - fonts, card data and art (`arena_assets.js`, which is generated by `arena_assets.py` from `art/img`);
  - `engine.js`, `bot.js`, `arena_audio.js` and `deckwiz.js`.
  - Each has a `/*__NAME__*/` placeholder in a `<script>` tag. A new module needs a placeholder plus a line in `build_arena.py`.
- **The built file must stay self-contained.** No network at runtime and no CDN libraries, because it is published as a claude.ai artifact and will be hosted on Netlify.
  - Inlined code can't contain `</script` or `</style` (the build asserts this).
- **Duels must stay deterministic.** A saved duel resumes by replaying only the human's decisions.
  - Anything that affects the game must use the engine's seeded `RNG`.
  - Never use `Math.random()` or `Date.now()` in game logic. UI-only randomness, like pack sparkle or idle-menu art, is fine.
- **Save keys are versioned.** Players' saves live in `localStorage`:
  - `rstcg-profile-v1`: GP, collection, decks, tutorial state;
  - `rstcg-arena-duel-v1`: the duel in progress;
  - `rstcg-settings`, `rstcg-arena-setup`, `rstcg-speed`.
  - Don't break their shape. If you must change it, migrate the old data, because Ramon has real progress saved.
- **UI text is plain English.** Short sentences, RuneScape flavour, no jargon.

- **Setup:** `npm install`, then `npx playwright install chromium` for the browser tests. Python 3.9+ needs no packages. On Windows, `python3` may be `python` or `py`.
- **Screenshots:** the UI tests save them to `web/test/ui/shots/`, so you can see a change. Open the PNGs and look; don't trust the DOM alone.
- **Test hooks:**
  - `window.__arena` exposes `ui`, `render`, `act`, `profile`, `CARDS`, `deckRules` and more for Playwright.
  - New profiles get a "welcome / play the tutorial?" modal. Tests click `[data-do="tutskip"]` after load.

## How the Arena is put together (`web/arena.src.html`, about 4,100 lines)

**One stage, scaled to fit.** The page is a fixed stage 1920 wide, and `fit()` scales it to the window.
- The stage is 1080 tall, except in duels on screens wider than 16:9 (phones). There it is `clamp(1920*H/W, 864, 1080)`.
- Always use `SH()`, never 1080, for anything placed against the bottom.
- `stageFor(key)` sets the height for a screen.

**Rendering is string templates.** `render()` rebuilds `#stage` from `ui` state.
- Each screen is a function in the `SCREENS` map: `menuHTML`, `pickHTML`, `decksHTML`, `editorHTML`, `wizHTML`, `packsHTML`, `duelHTML`, and so on.
- `SWEEP` sets how menu screens slide between each other.

**Input goes through attributes, never per-element listeners.**
- Clicks: `data-do="action"` plus `data-v="value"` → `act(what, v)`, one big `switch`.
- Text: `data-input="key"` → one input handler near the editor's `edq`.
- Long-press/hover zoom: `data-zoom="Card Name"`.
- Controller: the gamepad code walks everything with `data-do`. `padDefault()` picks where its focus ring starts.

**The duel.**
- `newConfig()` → `buildGame(config)` → `runDuel(config, decisions)`.
- The human's choices come in through a promise-based agent.
- The bot is `botAgent(new HeuristicBot(seed))`, which adds the "thinking" pause and the move reveal.
- `saveGame()` stores `{config, decisions}` after every human decision.

**Animations replay the difference.**
- `snap(g)` takes a picture of the state; `settle(g)` and `playChanges()` compare the last picture with the new one.
- Cards fly, damage mills, and capes tick (`capeTick`). The board itself is always drawn from the real state.

**The tilted table.**
- `TABLE = {w:1920, h:780, tilt:30, pers:1500}`, rendered as `.scene` (perspective) > `.plane` (`rotateX`).
- `proj(x,y)` / `projRect` mirror the CSS 3D maths, for placing flat things over tilted ones.
- The HUD stays flat on top: your hand, the actions grid, the turn panel, End turn, the log tab and the bot's hand of card backs.
- Rows: `ROW = {bot:8, you:522, h:250}`.

**Other systems.**
- **Tutorial:** a scripted first duel (`TUT_*`, `tutChoose`, `coachHTML`, `tutHighlight`) with stacked decks and a scripted bot. Then one-time tips in real duels (`TIPS`). Finishing gives a free pack.
- **Collection and economy:** you start with the three starter decks' cards, and basic materials are unlimited.
  - GP: 100 per win, 50 per loss. A 6-card pack (3 Common / 2 Uncommon / 1 Rare, sometimes Legendary) costs 200 GP.
  - Deck rules: exactly 60 cards, ≤4 copies, ≤1 Legendary, and only cards you own. `deckRules()` checks them.
- **Deck Wizard:** `deckwiz.js` (`window.RSTCGWiz`) builds a deck around up to 2 focus cards from what you own. It adapts the Starter/Tournament lists, then tests candidates with greedy-vs-greedy games and keeps the best. The UI is `wizHTML` / `wizBuild`.
- **Audio:** `arena_audio.js`, all synthesised, no sound files. It has music layers, an "intense" layer that latches on once either deck is ≤10, and sfx by name: `sfx('tick')` etc.

## Gotchas already paid for

- **`zoom` on an absolutely positioned element also scales its `left`/`top`.** Wrap it in an abs-positioned div and zoom the inner element. This is how the discard pile vanished once.
- **Animations in `render()` replay on every render**, because everything is rebuilt. Only animate on a new state, via a class like `.fresh`, or they flicker and look washed out.
- **Card names contain spaces and apostrophes** (`Iban's Staff`, `Green D'hide Body`). Use `esc()` in templates, and never `split(' ')` legal actions.
- **"Elemental Rune" in a card's `req` is not a card.** It means any of Air/Water/Earth/Fire.
- **Hover zoom is mouse-only** (`mouseover`), and the deck editor uses right-click to remove a card. Phones need alternatives (see `HANDOFF.md`).
